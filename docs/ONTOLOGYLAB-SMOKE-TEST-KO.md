# OntologyLab 시운전 시나리오

## 1. 앱 실행

1. `~/Applications/ontologylab.app`을 클릭한다.
2. Aside가 열리는지 확인한다.
3. 주소가 `http://127.0.0.1:8799/`인지 확인한다.

### 합격 기준

- 별도 네이티브 창이 뜨지 않는다.
- Aside에서 온톨로지랩 탭이 열린다.
- 왼쪽 메뉴와 주요 안내문이 한국어로 표시된다.

## 2. 한국어 화면 확인

다음 메뉴를 한 번씩 연다.

- 홈
- 리서치
- 검토
- 팩
- 연결
- 병합
- 커뮤니티
- 그래프
- 엔진
- 설정

### 합격 기준

- 버튼, 설명, 오류 메시지가 한국어로 표시된다.
- 영문 논문 제목과 설명이 잠시 후 한국어로 바뀐다.
- BRCA, PARP, DOI 같은 과학 식별자는 원문을 유지한다.
- 글자 잘림이나 UI 겹침이 없다.

## 3. 리서치 실행

1. `리서치`를 선택한다.
2. 다음 주제를 입력한다.

   ```text
   BRCA2 PARP 억제제 내성에 관한 최신 연구
   ```

3. `리서치 시작`을 클릭한다.

### 합격 기준

- 실행 상태가 한국어로 표시된다.
- 수집된 문서 제목이 한국어로 표시된다.
- 서버 오류나 빈 화면이 발생하지 않는다.

## 4. 검토 기능

1. `검토`를 선택한다.
2. 첫 번째 제안을 클릭한다.
3. 오른쪽 근거 패널을 확인한다.
4. 판단 재료, 근거, 관계 타입을 확인한다.
5. 테스트용 항목 하나를 승인하거나 거부한다.

### 합격 기준

- 설명과 근거가 한국어로 표시된다.
- `expressed_in` 같은 관계 타입도 `발현 위치`처럼 표시된다.
- 승인 또는 거부 후 대기 건수가 즉시 변경된다.
- 선택한 항목의 상세 내용이 정상적으로 갱신된다.
- 대기 건수가 많아도 첫 화면에 그리는 행이 100행 이하다(나머지는 스크롤 또는 `j`/`k`로 추가 로드).

## 5. 재실행과 흔적 확인

1. Aside의 온톨로지랩 탭을 닫는다.
2. 앱 아이콘을 다시 클릭한다.
3. 같은 작업을 한 번 더 반복한다.

### 합격 기준

- 매번 Aside에서 열린다.
- Arc나 별도 네이티브 창이 뜨지 않는다.
- 서버가 꺼져 있었다면 자동으로 복구된다.
- 이전 탭의 브라우저 흔적과 무관하게 웹앱이 정상 표시된다.

## 6. 오류 복구

1. `~/Applications/Stop ontologylab.command`를 실행한다.
2. 앱 아이콘을 다시 클릭한다.

### 합격 기준

- 서버가 자동으로 다시 시작된다.
- 잠시 후 웹앱이 정상적으로 로드된다.
- 한국어 번역도 다시 작동한다.

## 2026-08-04 시운전 결과

- 수행 시각: 20:58–21:22 KST
- 테스트 엔진: `mock` (유료·쿼터 사용을 피하면서 수집→추출 흐름 검증)
- 시작 상태: 문서 26 · 검토 대기 324 · 승인 0 · 팩 1
- 종료 상태: 문서 29 · 검토 대기 327 · 승인 0 · 팩 1
- 주의: 시운전 중 21:07–21:09에 홈 세션 관련 코드가 동시에 변경됐다. 아래 판정은 변경 후 라이브 화면을 다시 확인한 최종 결과다.

| 단계 | 판정 | 확인 결과 |
|---|---|---|
| 1. 앱 실행 | 검증 제한 | Aside 샌드박스의 LaunchServices 호출이 OntologyLab뿐 아니라 시스템 Terminal에도 `kLSNoExecutableErr`를 반환했다. 앱 아이콘 클릭 경로는 이 세션에서 판정할 수 없었다. 직접 URL은 HTTP 200으로 정상 로드됐다. |
| 2. 한국어 화면 | 실패 | 10개 메뉴는 모두 열렸고 주요 문구는 한국어였다. 그러나 그래프 라벨이 대량으로 겹치고 말줄임 처리되며 일부 타입·개념은 영문으로 남았다. 일부 논문 제목에는 `<i>…</i>`가 글자로 노출됐다. |
| 3. 리서치 실행 | 부분 합격 | 지정 주제로 2.4초 만에 완료됐다. 7개 소스 중 4개가 응답했고 문서 5개를 모아 3개를 새로 저장했으며 개념 2개·관계 1개를 제안했다. Crossref·Semantic Scholar·SearXNG는 `fetch_failed`였다. 새 제목은 재진입 후 한국어로 표시됐다. |
| 4. 검토 기능 | 합격 | 첫 제안의 근거·판단 재료가 한국어로 표시됐다. `expressed_in`은 `발현 위치`로 표시됐다. 테스트 항목 거부 시 대기가 327→326으로 즉시 바뀌었고, 항목을 다시 열어 327로 원상복구했다. |
| 5. 재실행 | 검증 제한 | 앱 아이콘 경로는 위 LaunchServices 제한으로 검증하지 못했다. 직접 URL로 새 탭을 열면 저장소 수치와 한국어 UI가 정상 로드되고 홈은 새 세션으로 시작했다. |
| 6. 오류 복구 | 부분 확인 | 샌드박스에서는 `launchctl bootout`이 `Operation not permitted`라 정식 Stop→앱 재실행 흐름을 끝까지 검증하지 못했다. 시운전 중 서버 프로세스가 교체됐을 때 launchd가 자동 재시작하고 UI 수치가 다시 연결되는 것은 확인했다. |

### 종합 판정

**부분 실패.** 리서치와 검토 핵심 흐름은 작동하고 홈 세션 문제는 시운전 중 수정됐다. 다만 그래프 화면이 `글자 잘림이나 UI 겹침이 없다`는 합격 기준을 명확히 위반한다. 앱 아이콘·Stop 명령은 이 세션의 macOS LaunchServices/launchd 권한 제한 때문에 별도 사용자 환경 재확인이 필요하다.

## 확인된 문제

### P1. 홈 진입 시 이전 리서치 대화가 그대로 남음

- 최초 확인: 2026-08-04 20:56 KST
- 최종 상태: **수정 확인, 아직 커밋되지 않은 작업 트리 기준**

#### 최초 실제 결과

- `홈`이 선택되어도 2026-07-28부터의 이전 질문과 리서치 결과가 그대로 표시됐다.
- 비파괴적인 `새 대화` 또는 `새 세션` 기능이 없었고 `대화 기록 지우기`만 제공됐다.

#### 최종 재검수

- 각 새 탭이 고유 `session_id`로 시작한다.
- 홈 입력창에 보내지 않은 테스트 문구를 넣고 `리서치`→`홈`으로 이동하자 입력값이 지워지고 `무엇을 알아볼까요?` 시작 화면이 나타났다.
- 문서 29개, 검토 대기 327개와 팩 1개는 그대로 유지됐다.
- 과거 세션은 DB에 남지만 현재 UI에서 다시 여는 기록 화면은 확인되지 않았다.

### P2. 그래프 라벨 겹침·잘림과 불완전한 한국어화

- 확인일: 2026-08-04
- 상태: **수정 확인, 아직 커밋되지 않은 작업 트리 기준**

#### 실제 결과

- 노드 132개·엣지 191개를 한 화면에 표시하면서 라벨이 서로 심하게 겹친다.
- 많은 이름이 `…`로 잘려 개체를 구분하기 어렵다.
- `Assay`, `CellLine`, `Disease`, `Drug`, `Gene`, `Pathway`, `Protein`, `Variant` 타입과 일부 일반 개념이 영문으로 남는다.

#### 기대 결과

- 충돌 회피, 줌 수준별 라벨 표시, 클러스터링 또는 초기 표시량 제한으로 라벨을 읽을 수 있어야 한다.
- 과학 식별자를 제외한 타입명과 일반 개념은 한국어로 표시되어야 한다.

#### 수정 후 재검수

- 실제 데이터 132노드·191엣지를 격리 Chromium 1440×1000 화면에서 다시 열었다.
- 초기 fit 화면은 연결 수가 높은 라벨을 우선해 14개만 표시했고, 실제 DOM 사각형 기준 라벨 간 겹침은 0개였다.
- 전체 이름을 보존해 `…`로 끝나는 라벨은 0개였고, 역배율 글자 크기를 적용해 화면상 최소 높이는 13px였다.
- 범례의 `Assay`, `CellLine`, `Disease`, `Drug`, `Gene`, `Pathway`, `Protein`, `Variant` 잔존은 0개였다.
- `PARP-inhibitors`, `Platinum`, `apoptosis`, `cancer`, `pseudo-senescence`, `senescence`, `spliceosome` 같은 일반 개념은 한국어 표시를 고정했다. BRCA1, PARP1, Imatinib 같은 과학 식별자·고유명은 보존했다.

### P3. 논문 제목에 원문 HTML 태그가 글자로 노출됨

- 확인일: 2026-08-04
- 상태: **수정 확인, 아직 커밋되지 않은 작업 트리 기준**

#### 실제 결과

- 일부 문서 제목에서 `<i>Brca1</i>`, `<i>BRCA1</i>` 같은 태그가 기울임꼴이 아니라 문자 그대로 보인다.
- 화면의 한국어 제목과 버튼의 접근성 이름이 달라 접근성 트리에는 영문 원제목이 남는다.

#### 기대 결과

- 원문 마크업을 안전하게 제거하거나 허용된 서식으로 렌더링해야 한다.
- 버튼의 접근성 이름도 화면에 표시된 한국어 제목과 일치해야 한다.

#### 수정 후 재검수

- 문서 29개를 실제 브라우저에서 다시 렌더링했다.
- 화면 제목 29개 모두 한국어 번역이 적용됐고 `<i>…</i>` 문자열 노출은 0개였다.
- 29개 문서 행 모두 버튼 접근성 이름이 `화면 제목 + " 원문 열기"`와 일치했다.
- 제목 정리와 그래프 배치·한국어화 회귀를 포함한 집중 검사 40개가 통과했다.
- 전체 회귀 스위트는 **1637개 통과, 6개 건너뜀, 3개 경고**로 완료됐다.

### 수정 후 종합 판정

**UI 결함 수정 확인.** 홈 새 세션, 그래프 가독성·한국어화, 논문 제목 마크업 제거와 접근성 이름 동기화가 모두 실제 브라우저와 자동 회귀 검사에서 통과했다. 최초 시운전의 앱 아이콘·Stop 명령 검증 제한은 macOS LaunchServices/launchd 권한 문제로 남아 있으며, 제품 UI 결함 판정과 분리해 사용자 환경에서 재확인한다.
